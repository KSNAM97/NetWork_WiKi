# IPv4 주소

## 개요

- IP Header에 포함된 주소
- Local 네트워크 → Remote 네트워크 통신 시 사용
- **10진수 32bit** 구성 (A.B.C.D)
- 범위: `0.0.0.0` ~ `255.255.255.255` (약 43억 개)

---

## 서브넷 마스크

- IP 주소에서 **Network 부분**과 **Host 부분**을 구분
- 연속된 1비트(Network) + 연속된 0비트(Host)로 구성

```
IP:   192.168.10.100  = 11000000.10101000.00001010.01100100
Mask: 255.255.255.0   = 11111111.11111111.11111111.00000000
                        └──────────────────────┘└────────┘
                              Network 부분       Host 부분
```

### CIDR 표기

| 표기 | 서브넷 마스크 | 호스트 수 |
|------|-------------|---------|
| /8 | 255.0.0.0 | 16,777,214 |
| /16 | 255.255.0.0 | 65,534 |
| /24 | 255.255.255.0 | 254 |
| /25 | 255.255.255.128 | 126 |
| /26 | 255.255.255.192 | 62 |
| /27 | 255.255.255.224 | 30 |
| /28 | 255.255.255.240 | 14 |
| /30 | 255.255.255.252 | 2 |

## Wildcard Mask

- **EIGRP, OSPF** 같은 Routing Protocol에서 네트워크 범위를 지정할 때 사용
- **ACL** 등 Filtering 기능에서 대상 네트워크 범위를 지정할 때 사용

### Subnet Mask와의 차이점

| 구분 | Subnet Mask | Wildcard Mask |
|------|-------------|----------------|
| 구성 | 32bit, 1과 0의 **연속적인** 형식만 가능 | 32bit, 1과 0의 **불연속** 형식 가능 |
| 1의 의미 | Network(공통비트) | 비공통비트 |
| 0의 의미 | Host(비공통비트) | 공통비트 |

### 변환 예시

| CIDR | Subnet Mask | Wildcard Mask | 범위 |
|------|-------------|----------------|------|
| 192.168.1.0/24 | 255.255.255.0 | 0.0.0.255 | 192.168.1.0 ~ 192.168.1.255 |
| 172.16.0.0/16 | 255.255.0.0 | 0.0.255.255 | 172.16.0.0 ~ 172.16.255.255 |
| 10.0.0.0/8 | 255.0.0.0 | 0.255.255.255 | 10.0.0.0 ~ 10.255.255.255 |
| 192.168.1.0/27 | 255.255.255.224 | 0.0.0.31 | 192.168.1.0 ~ 192.168.1.31 |
| 192.168.1.64/26 | 255.255.255.192 | 0.0.0.63 | 192.168.1.64 ~ 192.168.1.127 |
| 192.168.1.1/32 (Host) | 255.255.255.255 | 0.0.0.0 | 192.168.1.1 (단일 호스트) |

> Wildcard Mask는 Subnet Mask의 **반전(255 - 옥텟값)** 값과 같다. 예: 255.255.255.224 → 0.0.0.31

### 예제: 172.168.0.0/24 ~ 172.168.3.0/24 범위를 Wildcard Mask로 지정

```
172.168.000000 00.00000000
172.168.000000 01.00000000
172.168.000000 10.00000000
172.168.000000 11.11111111
──────────────────────────
  0 .  0.000000 11.11111111 = 172.168.0.0  0.0.3.255   (Wildcard Mask)
255.255.111111 00.00000000 = 172.168.0.0  255.255.252.0 (같은 범위를 Subnet Mask/CIDR로 표기)
```

```
! EIGRP/OSPF에서 Wildcard Mask 사용 예
Router(config-router)# network 172.168.0.0 0.0.3.255

! ACL에서 Wildcard Mask 사용 예
Router(config)# access-list 10 permit 172.168.0.0 0.0.3.255
```

## VLSM (Variable Length Subnet Masking)

- 클래스 기반이 아닌 **서브넷 마스크 기반**으로 IP 주소를 효율적으로 분할
- 필요한 호스트 수에 맞게 서브넷 크기를 가변적으로 설정
- CIDR과 함께 사용하여 라우팅 테이블을 줄이는 데 활용

### 예제: R1 - R2 - R3 구간에 192.168.1.0/24 할당

**조건**: 192.168.1.0/24 대역 하나로 R1↔R2, R2↔R3 두 개의 라우터 간 링크(호스트 2개 필요)와 R1·R2·R3에 각각 붙은 LAN 3개(호스트 30개 필요)를 모두 커버해야 한다.

- Host 30 필요 → `2^n - 2 ≥ 30` → n=5 → `/27` (255.255.255.224)
- Host 2 필요(라우터 간 링크) → `2^n - 2 ≥ 2` → n=2 → `/30` (255.255.255.252)

```
LAN용 /27 : 192.168.1.0/27, 192.168.1.32/27, 192.168.1.64/27
링크용 /30 : 192.168.1.96/30 (R1-R2), 192.168.1.100/30 (R2-R3)
```

```
! R1
interface GigabitEthernet0/0
 ip address 192.168.1.1 255.255.255.224   ! LAN (192.168.1.0/27)
interface Serial0/0/0
 ip address 192.168.1.97 255.255.255.252  ! R1-R2 링크

! R2
interface GigabitEthernet0/0
 ip address 192.168.1.33 255.255.255.224  ! LAN (192.168.1.32/27)
interface Serial0/0/0
 ip address 192.168.1.98 255.255.255.252  ! R1-R2 링크
interface Serial0/0/1
 ip address 192.168.1.101 255.255.255.252 ! R2-R3 링크

! R3
interface GigabitEthernet0/0
 ip address 192.168.1.65 255.255.255.224  ! LAN (192.168.1.64/27)
interface Serial0/0/0
 ip address 192.168.1.102 255.255.255.252 ! R2-R3 링크
```

### 예제: R1-R2-R3-R4 4개 라우터 구간에 211.241.20.0/24 할당 (심화)

**조건**: 211.241.20.0/24 대역 하나로 R1(Host 60), R2(Host 80), R3(Host 25), R4(Host 12) LAN 4개와 R1-R2, R2-R3, R3-R4 라우터 간 링크(각 Host 2) 3개를 모두 커버해야 한다. 필요 호스트 수가 큰 구간부터 순서대로 분할한다.

- Host 80 필요 → `2^n - 2 ≥ 80` → n=7 → `/25` (255.255.255.128)
- Host 60 필요 → `2^n - 2 ≥ 60` → n=6 → `/26` (255.255.255.192)
- Host 25 필요 → `2^n - 2 ≥ 25` → n=5 → `/27` (255.255.255.224)
- Host 12 필요 → `2^n - 2 ≥ 12` → n=4 → `/28` (255.255.255.240)
- Host 2 필요(링크 × 3) → `2^n - 2 ≥ 2` → n=2 → `/30` (255.255.255.252)

```
1단계) 211.241.20.0/24 → /25 두 개로 분할
211.241.20.0/25    (211.241.20.0   ~ 211.241.20.127)   ← R2 LAN (Host 80)
211.241.20.128/25  (211.241.20.128 ~ 211.241.20.255)

2단계) 211.241.20.128/25 → /26 두 개로 분할
211.241.20.128/26  (211.241.20.128 ~ 211.241.20.191)   ← R1 LAN (Host 60)
211.241.20.192/26  (211.241.20.192 ~ 211.241.20.255)

3단계) 211.241.20.192/26 → /27 두 개로 분할
211.241.20.192/27  (211.241.20.192 ~ 211.241.20.223)   ← R3 LAN (Host 25)
211.241.20.224/27  (211.241.20.224 ~ 211.241.20.255)

4단계) 211.241.20.224/27 → /28 두 개로 분할
211.241.20.224/28  (211.241.20.224 ~ 211.241.20.239)   ← R4 LAN (Host 12)
211.241.20.240/28  (211.241.20.240 ~ 211.241.20.255)

5단계) 211.241.20.240/28 → /30 네 개로 분할 (라우터 간 링크용)
211.241.20.240/30  ← R1-R2 링크
211.241.20.244/30  ← R2-R3 링크
211.241.20.248/30  ← R3-R4 링크
211.241.20.252/30  ← 예비
```

> 필요 호스트 수가 가장 큰 서브넷부터 먼저 분할하고, 남는 대역을 다시 절반씩 쪼개어 다음으로 큰 요구사항에 할당하는 방식으로 낭비를 최소화한다.

## 주소 요약 (Summary)

여러 네트워크를 하나의 주소로 묶어 라우팅 테이블 축소

```
예시: 121.160.8.0/24 ~ 121.160.15.0/24 → 121.160.8.0/21

121.160.00001 000.00000000
121.160.00001 001.00000000
121.160.00001 010.00000000
121.160.00001 011.00000000
121.160.00001 100.00000000
121.160.00001 101.00000000
121.160.00001 110.00000000
121.160.00001 111.00000000
─────────────────────────
255.255.11111 000.00000000 = 255.255.248.0 → /21
```

## IOS XE 16.x / 17.x 관점

### IPv4 주소 설정 — 인터페이스 문법 변화 없음

IPv4 주소 설정 명령어 자체는 IOS XE 16.x/17.x에서도 동일하게 유지됨

```
! IOS 15.x / IOS XE 16.x/17.x 동일 문법
interface GigabitEthernet0/0
 ip address 192.168.1.1 255.255.255.0
 no shutdown
```

### IPv4/IPv6 듀얼스택 (`IOS XE 16.x+`)

IOS XE 16.x부터 IPv6 듀얼스택이 기본 지원 — 엔터프라이즈 설계에서 IPv4와 병행 운영

```
! 듀얼스택 설정 (IOS XE 16.x+)
ipv6 unicast-routing                       ! IPv6 라우팅 활성화

interface GigabitEthernet0/0
 ip address 192.168.1.1 255.255.255.0      ! IPv4
 ipv6 address 2001:db8:1::1/64            ! IPv6 글로벌 유니캐스트
 ipv6 address fe80::1 link-local          ! IPv6 링크 로컬
 no shutdown
```

### IPAM 연동 — IP 주소 관리 자동화 (`IOS XE 17.x`)

IOS XE 17.x + DNA Center 환경에서 IP 주소를 중앙 IPAM으로 자동 관리

```
! IP 주소 할당 현황 확인 (IOS XE 동일)
R# show ip interface brief           ! 인터페이스별 IP 상태
R# show ip interface GigabitEthernet0/0   ! 상세 정보 (Secondary IP 등)

! Secondary IP (IOS XE 동일)
interface GigabitEthernet0/0
 ip address 10.0.0.1 255.255.255.0
 ip address 172.16.0.1 255.255.255.0 secondary
```

| 버전 | IP 주소 관련 변화 |
|------|----------------|
| IOS 15.x (Phase 2) | Classful/Classless, VLSM, 수동 설정 |
| IOS XE 16.x+ | 듀얼스택 기본 지원, NETCONF로 IP 설정 자동화 가능 |
| IOS XE 17.x | DNA Center IPAM 연동, IPv6 SLAAC/DHCPv6 표준화 |
